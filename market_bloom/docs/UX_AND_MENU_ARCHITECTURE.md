# UX and Menu Architecture

## UX Principles

PoMarket should remain easy to understand while becoming more layered over time. The core experience should still work in a few seconds, but the menu and progression systems should create a stronger sense of momentum and identity.

## Core Experience Loop

The app should continue to center around one core loop:

1. Enter the market.
2. Interact with the store zones.
3. Serve customers.
4. Earn coins and progress.
5. Upgrade the shop and unlock new possibilities.

This loop should remain the main path, and all menus should support it rather than interrupt it.

## Navigation Architecture

### Primary surface

The main game screen remains the center of gravity. It should contain:

- the market view,
- the player controls,
- the status bars,
- quick access to progression and shop systems.

### Secondary surfaces

These should appear as contextual overlays or sheets rather than full-screen transitions:

- Store upgrades.
- Monetization and reward offers.
- Meta-hub and progression summary.
- Daily bonus and event prompts.
- Onboarding and tutorial guidance.

## Information Architecture

### Top-level sections

- Play
- Progress
- Shop / rewards
- Profile / achievements
- Settings

### Suggested hierarchy

- Main market view
  - Brief status summary
  - Current quest or objective
  - Upgrade shortcuts
  - Reward actions
- Meta hub
  - Progression overview
  - Achievements
  - Statistics
  - Collections and milestones
- Shop layer
  - Cosmetic and functional offers
  - IAP and ad reward flows
  - Premium benefits

## Menu Design Principles

- Avoid forcing players through too many layers.
- Keep important actions reachable within one tap.
- Use short labels, clear icons, and immediate feedback.
- Make “next best action” obvious without being pushy.

## Onboarding Flow

The onboarding should remain lightweight but informative.

Suggested flow:

1. Welcome and purpose of the game.
2. Introduce the basic station interactions.
3. Guide the player through one simple customer cycle.
4. Introduce the first upgrade and first reward loop.
5. Allow the player to self-direct after that.

The onboarding should feel like guidance, not an interruption.

## Progression UX

Progression should be communicated through clear signals:

- Store level.
- Unlocks and new zones.
- Milestones and reward bursts.
- Quest completion states.
- Visible business growth.

The player should never need to guess whether they are making progress.

## Reward and Motivation UX

The game should maintain an always-present sense of momentum through:

- instant rewards,
- milestone celebrations,
- limited-time offers,
- visible shop upgrades,
- daily check-ins.

Rewards should feel meaningful but not exploitative.

## Recommended UX Enhancements

### Short-term improvements

- Make upgrade affordances clearer with better preview text.
- Improve the readability of the current goal and reward state.
- Introduce a more obvious “what should I do next?” cue.

### Mid-term improvements

- Add a lightweight progression hub with curated milestones.
- Surface active offers and bonuses more clearly.
- Improve state clarity for inventory, queue, and sales feedback.

### Long-term improvements

- Add richer event-based menus and themed overlays.
- Introduce a more personalized dashboard for player habits and progress.
- Create a richer social or sharing layer without introducing friction.

## Navigation Pattern Recommendation

Keep the experience mostly single-screen and sheet-driven. That approach fits the current design and preserves the game’s simplicity. The app should avoid becoming a maze of nested pages.

## UX Success Metrics

The UX should be judged by:

- time to first meaningful loop completion,
- average session return rate,
- upgrade discoverability,
- player understanding of progression,
- clarity of reward moments.
